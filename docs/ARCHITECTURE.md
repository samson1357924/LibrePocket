# LibrePocket 架構設計（ARCHITECTURE）

> 定位：Android 端離線優先的個人 AI 助理殼 + 可插拔模型後端 + 分級系統能力。
> 本文只定義結構、邊界與語義，不規定具體業務程式碼實作細節。
> 術語為本專案原創表述；競品僅借鑑思想，見 §12。

## 1. 設計目標與非目標

### 1.1 目標

- 同一套 Agent 核心可在多種系統入口下運作（主 App、快捷方式、分享、語音喚起等），且入口增刪不改核心。
- 後端模型可由使用者自帶金鑰（BYOK）切換，不綁定單一供應商。
- 所有「會改變外部世界」的能力都經過結構校驗、能力投影與使用者授權三道閘門。
- 操作分快慢兩條路徑：確定性系統操作走快通道；需要看懂螢幕、逐步試錯的走慢通道。
- 敏感資料預設不落地、不上傳，在記憶與日誌層可證明已被遮蔽。
- Play 上架版本與完整版本共用同一程式碼基線，僅以編譯風味（flavor）開關能力。

### 1.2 非目標

- 不自研大模型，不在端側做訓練或微調。
- 不承諾免 Root 達成全自動化；做不到的能力明確降級而非靜默失敗。
- 不把 Root / Shizuku / Xposed 類機制作為主流程依賴，僅作可選增強。

## 2. 分層總覽

```text
┌────────────── 入口層 Entry Layer ──────────────┐
│ Launcher Activity / Tile / Shortcut / Share / │
│ Voice / Notification Reply / Widget           │  只負責：收集意圖 + 轉交會話
└──────────────────────┬────────────────────────┘
                       ▼
┌────────────── 會話編排層 Session ──────────────┐
│ 會話存儲 / 輪次裝配 / 預算 / 中斷語義          │  唯一有狀態中樞
└──────────────────────┬────────────────────────┘
                       ▼
┌────────────── 代理核心 Agent Runtime ──────────┐
│ FastRouter ──→ 確定性工具鏈（Intent 優先）     │
│ SlowRouter ──→ 螢幕理解 + 逐步動作 + 仲裁      │
│ Tool Schema 校驗 / 能力投影 / 脫敏 / 轉錄      │
└──────────────────────┬────────────────────────┘
                       ▼
┌────── 能力適配層 Capability Adapters ──────────┐
│ SystemOps / Media / Files / Terminal / Linux  │
│ 免Root 實作 / Shizuku 實作 / Root 實作        │
└──────────────────────┬────────────────────────┘
                       ▼
┌────── 外部連接層 External ────────────────────┐
│ Provider 三協議 / MCP 客戶端 / Skills / 記憶庫 │
└───────────────────────────────────────────────┘
```

分層規則：上層可呼叫下層，下層不得反向依賴上層；跨層資料只走定義好的資料物件，不直接傳 Android `Context` 給核心。

## 3. Runtime 與入口解耦

### 3.1 原則

- `AgentRuntime` 是純邏輯單元：輸入為「已裝配的輪次請求」，輸出為「事件串流」，不持有 Activity、Service 或 View 引用。
- 所有 Android 入口（Entry Point）只做三件事：
  1. 建立或恢復一個會話 ID；
  2. 把使用者輸入正規化為 `UserTurn`（文字 / 語音轉文字 / 檔案 / 結構化命令）；
  3. 訂閱 Runtime 事件串流並渲染。
- 入口之間不共享可變狀態；共享狀態只存在於會話存儲層。

### 3.2 事件串流

Runtime 對外只發出有限事件集合，例如：

- `TEXT_DELTA` / `TEXT_DONE`：模型文字增量與完成；
- `TOOL_CALL` / `TOOL_RESULT`：工具呼叫與結果摘要（非原始敏感值）；
- `CONFIRM_REQUEST`：需要使用者確認（高風險動作）；
- `STATE_CHANGE`：`IDLE / RUNNING / PAUSED / CANCELLED / WAITING_CONFIRM / ERROR`；
- `ROUTE_DECISION`：本輪走了快通道或慢通道及理由碼。

UI 層只允許根據事件渲染，禁止解析模型原始字串來觸發系統動作。

### 3.3 生命週期

- Runtime 與 `Activity` 生命週期無關；旋轉螢幕、切換 App 不中斷任務。
- 應用被系統回收時，會話存儲中的 `RUNNING` 任務在下次啟動時被標記為 `INTERRUPTED`，需使用者明確恢復才可繼續，不自動重放副作用動作。

## 4. Provider 三協議統一

### 4.1 動機

不同供應商的請求形狀、工具呼叫格式、串流事件差異大。若業務層直接對接，每新增一家就污染全域。因此設統一內部介面 `ModelProvider`，外部差異在轉接器內消化。

### 4.2 內部統一模型

內部只認識三種東西：

1. `ChatRequest`：系統提示、歷史輪次（已脫敏）、可用工具 Schema 子集、預算（最大步數 / token / 時間）。
2. `ChatStream`：文字增量、工具呼叫請求、結束原因（`STOP / TOOL / LENGTH / FILTERED / ERROR`）。
3. `ToolCallRequest`：`{ toolName, argumentsJson, callId }`，`argumentsJson` 在進入轉接器前已通過 Schema 校驗。

### 4.3 三協議轉接

支援三類線路協定（命名為 A / B / C 型，避免與廠商 SDK 綁定）：

| 內部概念 | A 型（訊息 + tool_calls） | B 型（內容塊 + tool_use） | C 型（parts + function_call） |
|---|---|---|---|
| 系統提示 | `system` 角色訊息 | 獨立 system 欄位 | 獨立 systemInstruction |
| 工具定義 | `tools: [{function:{name, parameters}}]` | `tools: [{name, input_schema}]` | `tools: [{functionDeclarations}]` |
| 串流增量 | `delta.content / delta.tool_calls` | `content_block_delta` | `candidates.content.parts` |
| 停止原因 | `finish_reason` | `stop_reason` | `finishReason` |

轉接器職責：協議欄位映射、增量事件歸一化、錯誤碼歸一化（限流 / 認證 / 內容過濾 / 超時）、重試策略（僅對冪等讀取自動重試，寫動作不自動重試）。

### 4.4 BYOK 與金鑰管理

- 金鑰由使用者自行填入，存於 Android Keystore -backed EncryptedPreferences，不以明文寫入資料庫或日誌。
- 每個 Provider 配置獨立存放：`{ baseUrl, keyRef, modelId, budgetDefaults }`。
- 切換模型不丟失會話歷史；歷史為供應商無關格式，轉接器在發送前即時翻譯。
- 匯出 / 備份時金鑰預設不包含，需使用者明確勾選且二次確認。

## 5. Tool Schema 校驗

### 5.1 定義

每個工具在註冊時宣告 JSON Schema（名稱、參數型別、必填項、取值範圍、副作用等級）。呼叫鏈：

```text
模型輸出 ToolCall → Schema 結構校驗 → 能力投影檢查 → 授權檢查 → 執行 → 結果脫敏 → 回填模型
```

任何一步失敗都不執行，且錯誤以結構化方式回填模型（`SCHEMA_ERROR / CAPABILITY_DENIED / AUTH_DENIED`），讓模型可自我修正而非崩潰。

### 5.2 副作用分級

- `READ`：讀取類（查日曆、列檔案、讀狀態），失敗可重試。
- `WRITE`：改變外部狀態（發郵件、建鬧鐘、寫檔），需冪等鍵或確認。
- `PRIVILEGED`：通訊與高敏感（撥號、簡訊、截圖分享、提權命令），一律走確認或系統接管（見 §9）。

未知工具名、超範圍列舉值、型別不符一律拒絕，不做模糊匹配。

## 6. 能力投影（Capability Projection）

### 6.1 動機

同一工具在不同裝置條件下可用性不同（有無 Root、有無 Shizuku、Play 版或完整版）。若把全部工具都暴露給模型，模型會規劃出執行不了的路徑。能力投影在每輪裝配提示前，根據當前裝置實際狀態計算「本輪可見工具子集」。

### 6.2 投影輸入

- 編譯風味：`play` / `full`；
- 執行期探測：Root 可用性、Shizuku 連通性、系統版本、授權狀態；
- 使用者開關：高風險類別是否啟用。

### 6.3 投影輸出

- 可見工具清單 + 每個工具的可用等級（`NATIVE / DEGRADED / UNAVAILABLE`）；
- 不可用原因碼（`FLAVOR_BLOCKED / NO_PRIVILEGE / USER_DISABLED`），供模型生成誠實的降級回覆；
- 投影結果寫入該輪轉錄頭部，保證事後可審計「模型當時看到了什麼」。

投影是純函數：相同輸入必得相同輸出，便於單元測試。

## 7. 迴圈語義：steering / cancel / pause

Agent 主迴圈預設為**單步串行**：一次只執行一個工具呼叫，完成後再決定下一步。平行僅允許在標記為 `READ` 且無依賴的多讀取合併時使用。

### 7.1 狀態機

```text
IDLE → RUNNING ⇄ PAUSED → (RESUMED→RUNNING)
RUNNING → CANCELLED / DONE / ERROR / WAITING_CONFIRM
WAITING_CONFIRM → RUNNING (批准) / CANCELLED (拒絕)
INTERRUPTED → RUNNING (使用者明確恢復) / CANCELLED
```

### 7.2 Steering（中途導向）

- 使用者在 `RUNNING` 或 `PAUSED` 時可插入新的 `UserTurn`。
- 語義：當前正在執行的原子工具呼叫不被搶占（讓其完成或超時），後續規劃立即以「舊目標 + 新指示」重新規劃。
- 新指示寫入同一會話為新輪次，不另起會話，保證轉錄連續。

### 7.3 Cancel（取消）

- 合作式取消：設定取消標誌，當前工具收到中斷訊號，阻塞型操作在下一個可中斷點退出。
- 已發出的外部副作用不回滾（如已發送的郵件），轉錄中如實記錄 `CANCELLED_AFTER_SIDE_EFFECT`。
- 取消後會話回到 `IDLE`，保留部分進度摘要供使用者追問。

### 7.4 Pause（暫停）

- 暫停用於「等我確認 / 等條件滿足」。慢通道的螢幕操作序列在步驟邊界停下，不停在點擊中途。
- 恢復時不重放已完成的寫動作，從下一個未執行步驟繼續，冪等鍵防止重複。

## 8. 轉錄（Transcript）與脫敏

### 8.1 轉錄結構

每輪持久化三段：

1. `header`：會話 ID、輪次號、路由決策、能力投影快照、模型 ID（不含金鑰）。
2. `events`：事件串流的完整有序記錄（含工具參數與結果摘要）。
3. `memo`：本輪壓縮摘要（供長會話壓縮上下文）。

底層以追加寫 JSON Lines 形式持久化，崩潰後可按行恢復；資料庫僅建索引，不作為唯一真相來源。

### 8.2 脫敏規則

- 進入轉錄前執行脫敏器：電話號碼、郵件地址、簡訊正文、通知全文、檔案絕對路徑中的使用者名稱、位置座標、Token/金鑰樣式字串，依規則替換為佔位符（如 `[PHONE_MASKED]`），原始值僅保留在記憶體中的執行上下文，不寫盤。
- 匯出轉錄 / 回報問題時預設匯出脫敏版；明文匯出需顯式開關並記錄審計事件。
- 脫敏器本身可單元測試：給定輸入語料，斷言輸出不含可匹配敏感正則的子字串。

## 9. 快慢雙通道：FastRouter / SlowRouter

### 9.1 FastRouter（快通道：確定性系統操作）

適用：導航、開啟 App、郵件草稿、鬧鐘、日曆、音樂播放、音量、通知查詢、截圖等**可用公開 Intent / 系統 API 直達**的操作。

原則：

- **Intent 優先**：能用隱式 Intent / 系統 Provider 完成的，不做螢幕點擊。
- 參數由 Schema 校驗後直接映射為 Intent 欄位；模糊目標（如「放點輕音樂」）先要求澄清或選用預設供應商，不猜測包名。
- 高風險動作（撥號、簡訊發送）一律轉交系統撥號 / 簡訊 App 完成（`ACTION_DIAL` 而非 `ACTION_CALL`，簡訊走系統編輯器預填），本 App 不直接發出。
- 每個快通道工具宣告超時與降級路徑（例如無地圖 App 時改為開啟網頁地圖）。

### 9.2 SlowRouter（慢通道：螢幕理解 GUI 操作）

適用：無公開 API、目標 App 未適配、跨 App 多步流程。

流程：

```text
截圖/無障礙節點（full 版限定）→ 螢幕語義壓縮 → 單步動作提議 →
仲裁（是否越界/是否需確認）→ 執行一步 → 觀測變化 → 迴圈或升級/放棄
```

約束：

- 慢通道僅在完整版且使用者明確授權自動化開關後可見（能力投影直接隱藏）。
- 每步動作需滿足「可觀測、可撤銷或可重試」三選一，否則要求確認。
- 設定步數與時間上限；超限自動降級為「生成手動操作指引」而非無限重試。
- 慢通道產生的座標/節點動作寫入獨立審計表，與快通道 Intent 調用區分統計。

### 9.3 路由決策

`RouteDecision` 由規則引擎先行判斷，模型只在規則無把握時仲裁：

1. 有確定性 Intent 模板 → Fast；
2. 目標可用能力投影為 `UNAVAILABLE` → 直接拒絕 + 指引；
3. 需讀屏或跨 App 狀態依賴 → Slow（若不可用則給手動指引）；
4. 其餘 → 預設 Fast，失敗一次後可升級 Slow（需授權）。

決策與理由碼寫入轉錄頭部。

## 10. MCP / Skills / 記憶三層

### 10.1 MCP（模型上下文協定客戶端）

- 本 App 作為 MCP 客戶端，可連接使用者配置的 MCP 伺服器以擴充工具（如檔案搜尋、票務系統）。
- MCP 工具在註冊時同樣走 Schema 校驗與能力投影；預設副作用等級為 `WRITE`，需逐伺服器授權。
- MCP 傳輸故障視為工具級錯誤，不中斷會話；連續失敗達閾值後該伺服器被暫時熔斷。

### 10.2 Skills（技能包）

- Skill = 一組提示片段 + 工具子集 + 前置檢查的打包體（例如「整理發票」「排會議」）。
- Skill 不直接執行程式碼，只約束規劃空間：啟用 Skill 後，模型可用工具被收斂到該 Skill 聲明的子集，減少誤調用。
- Skill 來源可為內建或使用者匯入；匯入時校驗簽名 / 雜湊並展示權限清單。

### 10.3 記憶三層

1. **工作記憶（Working）**：當前會話最近 N 輪原文，存記憶體，隨會話結束丟棄可重建部分。
2. **情節記憶（Episodic）**：跨會話的轉錄摘要 + 全文檢索索引（FTS），支援「上次幫我訂的餐廳」類回想。寫入前脫敏。
3. **語義記憶（Semantic）**：使用者長期偏好與事實（如常用導航 App、音樂服務），Key-Value + 向量/全文混合檢索，需使用者可檢視、可刪除單條。

三層共用同一脫敏器與同一授權面：記憶讀取需聲明用途，寫入需標註來源輪次，刪除需級聯清除索引。

## 11. 併發、預算與錯誤策略

- 預設串行；例外並行僅限唯讀合併，且由 Runtime 而非模型決定是否合併。
- 每輪預算：最大工具步數、最大耗時、最大近似 token，三者任一超限即停並生成部分結果摘要。
- 重試：`READ` 可退避重試；`WRITE` 不自動重試，需新一輪明確指令；`PRIVILEGED` 任何失敗都轉人工確認。
- 所有外部呼叫設超時；超時錯誤攜帶 `retryable` 旗標供上層決策。

## 13. 術語表

- Entry：系統入口，收集意圖的薄層。
- Runtime：無 Android 依賴的代理核心。
- Projection：按裝置與風味計算可見能力的純函數。
- Fast/Slow：確定性 Intent 路徑 vs 螢幕理解路徑。
- Transcript：JSONL 持久化的輪次事件真相來源。
- BYOK：使用者自帶模型金鑰。
